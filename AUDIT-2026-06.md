Findings from a 5-lens parallel audit (TTS parsing · item/class/build modeling & scoring ·
UX/UI · latent bugs/reliability · game-mechanics ground-truth). Every item is grounded in
real code (file:line). Severity = user impact; Effort = S/M/L; Conf = confidence the finding
is real. ⚑ = needs an in-game capture to confirm the tooltip shape before fixing.

The remaining issues are concentrated in (a) a few sharp correctness bugs, (b) crash-time
data-safety, (c) discoverability/empty-state UX, and (d) class/build coverage breadth.

## Tier A — Correctness bugs (the app shows the user wrong information)

- [x] **A1 · Mythic uniques can be verdicted "Junk".** _(v0.45.0)_ `GearParser` only sets `IsAncestral`
  when the literal word "Ancestral" is voiced; a Mythic tooltip without it leaves
  `IsAncestral=false`, and `Verdicts.For` (`Verdicts.cs:76`) then junks any non-ancestral
  item under IP 900. A Mythic is never junk. **Fix:** `IsMythic ⇒ IsAncestral=true` in
  `GearParser` (`:166/170`); also guard the floor rule with `&& !IsMythic && !IsUnique`.
  *Sev High · Eff S · Conf High*
- [x] **A2 · Residual vendor-gear-leak hole** _(v0.45.0 — positive Character panel now required)_ (found independently by 2 agents). A vendor/bag
  hover can still be stamped *worn* when `_currentPanel` is stale-"Character" (a missed
  Vendor/Purveyor marker) and the block closes with no action tail: `ClassifyContext`
  (`LogWatcher.cs:411`) trusts `UiPanel=="Character"`, and `GearParser.SlotHeaders` still
  contains vendor-ambiguous words (Ring/Neck/Ranged) that arm `FromCharPanel` without setting
  the panel. **Fix:** expire `_currentPanel` after N quiet lines, and require a corroborating
  Character signal (not bare `null`) in the no-action-tail branch. *Sev High · Eff M · Conf High*
- [x] **A3 · Skill-rank affixes mis-parse** _(v0.45.0)_ — the #2 highest-leverage affix in the game.
  `+3 Ranks to Core Skill` parses to affix text `"Ranks to Core Skill"` because
  `ReLeadingConnective` (`GearParser.cs:78`) only strips a *leading* "to ". `PhraseMatch`
  then under-matches build targets ("Core Skills" plural, umbrella "All Skills").
  **Fix:** strip a leading `Ranks?\s+to\s+`; add a `+N Ranks to X` fixture assertion.
  *Sev High · Eff S · Conf High*
- [x] **A4 · The "under-rolled / POLISH" guidance tier is effectively DEAD for imported builds.** _(WON'T-CHANGE — this is the DELIBERATE v0.42 tradeoff: the roll-quality gate was removed for presence-based scoring, and v0.42's own release notes named this exact fallout. Re-adding thresholds would reverse that decision. Working as designed.)_
  `MaxrollImporter.ParseItemAffixes` never sets `Min`/`MinPercent`, so `EvalSlot` always
  scores by presence and Status "under" can't fire — which silences `BuildGuide` IMPROVE/
  RE-TEMPER steps and the masterwork/GA `Activities` recs for every real import. **Fix:**
  decide intent — either derive an implicit threshold (harvest target maxima) on import, or
  remove the dead branches and document it. *Sev High · Eff M · Conf High*
- [x] **A5 · Aspect double-counting inflates completion %.** _(v0.47.0 — VERIFIED the gear-vs-Aspects "double count" was a misread: the per-slot aspect is display-only WantAspect, never in a group's Total; aspects count once, in the Aspects category. Fixed the one REAL case: deduped the global list so the same aspect on two slots isn't counted twice.)_ `MaxrollImporter` pushes each
  slot's imprinted aspect to BOTH the slot (`WantAspect`) and the global Aspects category
  (`:364`), which `Diff` re-checks independently — so a 6-aspect build adds 6 duplicate rows
  to `Total`. **Fix:** don't add slot-imprinted aspects to the global Aspects list.
  *Sev Med-High · Eff M · Conf High*
- [x] **A6 · A badly-rolled unique shows 100% met.** _(v0.48.0 — VALIDATED against the real Dance-of-Knives build + live.json: owned Shrouded Gift → 4/5 (missing Armor), Sea Lord's → 1/2 (missing Core Skills). Shipped as an ADVISORY `RollNote`: presence still counts the unique as met (v0.42 model, headline % unchanged), but a badly-rolled owned copy is now flagged to prompt chasing a better one. The counted variant was REJECTED — it balloons the Uniques total 5→~22 and double-penalizes UNOWNED uniques' secondaries, distorting the %.)_ `TargetUnique.Affixes` is imported but
  the Uniques diff (`DiffEngine.cs:571-584`) only checks presence by name; it never scores
  the owned copy's rolled secondaries (gearing doc §4 says treat uniques as rollable).
  **Fix:** run owned-unique secondaries through `EvalSlot` and surface under-rolled sub-rows.
  *Sev Med-High · Eff M-L · Conf High*
- [x] **A7 · GA count silently null when the temper line is missing/truncated.** _(v0.47.0 — Mythics now floor to all-GA from rarity; the per-affix/temper inference is unchanged for non-Mythics.)_ GA count is
  derived only from `TemperMax-3`; a poll-edge-truncated block or a tooltip without the temper
  line drops it to null and the item is graded GA-unknown. **Fix:** floor GA from rarity
  (Mythic ⇒ all GA); mark "GA unknown" distinctly from "0 GA". *Sev Med · Eff M · Conf Med*

## Tier B — Reliability / crash-time data safety

- [x] **B1 · Non-atomic writes corrupt data on crash.** _(v0.45.0 — live.json + profiles + active.json)_ `live.json` (`MainWindow:1085`) and
  `ProfileStore.Save` (`:62`) use plain `File.WriteAllText`; a kill mid-write truncates the
  file, which then silently deserializes to null/empty — the character's loadout, bound build,
  paragon/Torment vanish with no error. (Tombstones/icons already write atomically — match
  them.) **Fix:** temp-file + `File.Move(overwrite)`. *Sev High · Eff S · Conf High*
- [x] **B2 · Silent ~70 MB update download on every launch.** _(v0.45.0 — in-flight guard; auto-download-vs-prompt left as a product choice)_ `CheckForUpdatesAsync`
  (`MainWindow:1852`) auto-`DownloadUpdateAsync` (~70 MB) before the user sees any "update
  ready" UI, re-fires on every `StartWatching()` (each setting change / `SessionEnded`), and
  has no in-flight guard (two writers can race the staged file). **Fix:** prompt-then-download
  or gate behind a setting; add a "checked/​downloading this run" guard. *Sev High · Eff S · Conf High*
- [x] **B3 · OCR scan has no re-entrancy guard.** _(v0.45.0)_ `OcrCaptureEngine.ScanCoreAsync` mutates
  `_orderedGear/_orderedInv/_lastHash` with no lock; a >20 s scan lets the next timer tick
  start concurrently → torn lists / `IndexOutOfRangeException`. (`LogWatcher.Poll` already
  guards with `Interlocked`.) **Fix:** add the same skip-if-busy guard. *Sev Med-High · Eff S · Conf High*
- [x] **B4 · Negative-cache latches until restart.** _(v0.45.0 — no-negative-cache + atomic/self-healing caches)_ `GameDataIcons.GetDef` (`:251`) caches a
  `null` def on a single fetch failure → that atlas stays silhouettes for the whole process;
  `MaxrollImporter.LoadJsonCached` (`:441`) caches a truncated download (non-atomic write,
  `File.Exists` skip) → every future import/icon resolve throws until manual clear. **Fix:**
  don't cache negatives; atomic write + delete-on-parse-failure. *Sev Med-High · Eff S · Conf High*
- [x] **B5 · UTF-8 multibyte split across poll chunks** _(v0.51.0 — `LogWatcher.Poll` now streams UTF-8 via a persistent `Decoder` (reset on rotation); extracted a public `FeedBytes` seam mirroring `FeedChunk`, with a test that splits an accented name mid-character and fails under the old per-chunk decode.)_ — original: → mojibake in an accented item/char
  name, which then mis-keys dedup/tombstone/profile matching. `LogWatcher.Poll` keeps a partial
  *line* but decodes each byte chunk independently (`:160`). **Fix:** keep undecoded trailing
  bytes / use a streaming `Decoder`. *Sev Med · Eff M · Conf Med* ⚑(only bites non-ASCII names)
- [x] **B6 · "Adopt stray log" splices raw bytes into the live tail** _(v0.53.0 — now parses the stray OFFLINE via BuildFromLines and merges through OnLiveUpdate, so an embedded attach marker can't wipe the live loadout and there's no splice-seam mis-parse.)_ — original: (`MainWindow:667`) — if
  the stray contains an attach marker it wipes accumulated gear; otherwise the seam mis-parses.
  **Fix:** feed the stray through `BuildFromLines` offline and merge. *Sev Med · Eff M · Conf Med*
- [x] **B7 · Tombstone resurrection on replay (inventory path).** _(v0.45.0)_ During `_replayFromZero` the
  gear path skips `ObserveSightings`, but `_tombstones.Apply(inv)` (`MainWindow:603`) observes
  sightings unconditionally → deleted inventory items reappear after a live-gear clear. **Fix:**
  filter-only `Apply` (no observe) during replay. *Sev Med · Eff S · Conf Med*
